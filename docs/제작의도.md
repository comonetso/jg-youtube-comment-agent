# 제작 의도 — 유튜브 댓글 에이전트 대시보드

(주)제이지그룹 AI PM 선발 과제 TRACK 2 · 시연 영상 https://youtu.be/ZBi4pQLhUqY

## 한 줄로

지정 연애 채널 5곳의 영상을 불러와, AI가 **그 영상 속 실제 말**을 짚어 시청자처럼 댓글 초안을 쓰고, 버튼 한 번에 **크롬 '유튜브1' 프로필이 열려 한 글자씩 입력·게시·내 댓글 확인**까지 하는 내 컴퓨터용 대시보드입니다.

## 왜 이렇게 설계했나

### 1. 세 칸 — 처음 보는 사람도 설명 없이
① 영상 불러오기 → ② 영상 고르기 → ③ 댓글 달기. 칸마다 번호와 한 줄 안내를 두고, 진행 상태(프로필 여는 중 → 입력 중 n/N → 게시 완료·댓글 보기)와 실패 이유·캡처를 화면에 바로 보여 줍니다. 아래에는 시간순 게시 기록을 둡니다.

### 2. 맥락 이해 — "이 영상에서만 나올 수 있는 댓글"
- AI가 **자막(없으면 제목·설명)과 인기 댓글**을 먼저 읽고, 영상이 다루는 연애 고민을 한 줄로 정리한 뒤 그 영상을 본 시청자의 말투로 씁니다.
- 댓글이 짚은 말은 **근거 인용**으로 함께 받고, 코드가 그 인용이 **실제 자막·설명에 있는지 원문과 대조**합니다. 없는 장면을 지어내면 다시 쓰게 합니다.
- 같은 영상도 [다시 만들기] 할 때마다 다른 댓글이 나오고, 영상마다 짚는 말이 다릅니다.

### 3. 운명원 유도 — 자연스럽게, 그러나 거짓 후기 없이
- 운명원은 "잘 본다던데", "한번 보고 싶다"처럼 **들은 말이나 바람**으로만 언급합니다.
- "가 봤다·받아 봤다·봤는데 맞더라" 같은 **지어낸 이용 후기**와 링크·해시태그는 검사기가 걸러 다시 쓰게 합니다(과제 금지 조건).

### 4. 운영 규칙 — 화면이 아니라 서버 코드에서 강제
- **허용 범위**: 지정 채널 5곳과 본인 테스트 영상만. 링크를 직접 넣어도 영상의 **실제 채널 ID를 확인**해 막습니다.
- **영상당 1개 · 하루 10개**: 게시 직전에 예약을 먼저 기록합니다. 게시 결과가 불분명하면(눌렀는데 확인 못 함) 실제로 달렸을 수 있으니 그 영상도 잠급니다. 프로그램이 도중에 꺼져도 다시 켤 때 그 기록으로 잠금을 지킵니다.
- **기록**: 어느 영상에 · 어느 프로필로 · 무슨 댓글을 · 성공/실패/결과불명/연습을 시간순으로 남깁니다.

### 5. 실제 게시 — 다른 사람 PC에서도 되게
- 평소 쓰는 브라우저가 아니라 **Google Chrome 전용 프로필**(유튜브1)을 Playwright로 엽니다. 크롬만 있으면 누구 PC에서도 같은 방식으로 돌아갑니다.
- 댓글창을 열고 **한 글자씩 입력 → 게시 → 목록에서 내 계정·본문이 같은 댓글을 찾아 확인**합니다. 성공·실패 모두 화면 캡처를 남깁니다.
- 영상 읽기와 게시는 **프로필을 나눠** 씁니다(읽기 = 로그인 없는 프로필). 같은 프로필을 번갈아 열면 잠금이 겹쳐 멈추거나 로그인이 늦게 읽히는 문제를 실측으로 확인하고 나눴습니다.

### 6. 안전과 규정 — 점수보다 먼저 지킨 선
- **실제 게시는 본인 채널의 '일부 공개' 테스트 영상에서만** 했습니다. 시청자인 척하는 홍보 댓글을 남의 채널에 실제로 다는 것은 유튜브 스팸 정책과 국내 광고 표시 지침(경제적 이해관계 표시, 2026년 AI 가상인물 표시)에 걸릴 수 있다고 판단했습니다. 테스트 영상 설명란에도 시연용임을 적었습니다.
- **광고 표시는 설정으로**(`config.json` 의 `comment.adLabel`). 시연은 과제 기준(시청자처럼 자연스럽게)에 맞춰 꺼 두었고, **실제 운영 때는 켜야 한다**고 봅니다 — 켜면 모든 댓글 맨 앞에 "[광고]"를 붙이고 검사기가 강제합니다.
- 유튜브는 '자동 조종 중' 표시가 켜진 크롬에는 자막 본문을 비워 보냅니다. 이 표시를 끄는 옵션은 **로그인 없는 읽기 전용 프로필에만** 쓰고, **게시용 프로필에는 쓰지 않았습니다** — 게시 쪽 감지를 피하면 스팸 차단을 우회하는 도구가 되기 때문입니다.

## AI를 어떻게 썼나 — 사람이 결정하고, AI 여럿이 나눠 만들고, 다른 AI가 검증

- **Claude Code(총괄)**: 과제 분석, 모듈 경계와 약속(계약 문서) 설계, 공용 부품 작성, 통합·시험·녹화.
- **병렬 에이전트 5개**(워크플로우): 수집 · 게시 · AI 댓글 · 화면과 규칙을 **파일이 겹치지 않게 동시에** 구현하고, 다섯 번째가 전체를 연결해 끝까지 돌려 보며 연결 버그를 고쳤습니다(약 47분).
- **Codex(다른 회사 AI, 2회 상담)**: ① 제작 전 견적·스택·정책 위험 검토 ② "전용 크롬에서만 자막이 0자" 원인 조사 — 확인값(pot)이 거절되는 경로를 실험으로 좁혀 줬고, 마지막 분기는 Claude가 이 PC에서 직접 관측해 원인(자동 조종 표시)을 확정했습니다.
- **사람(지원자)이 내린 결정**: 다른 PC에서 재현되도록 브라우저 방식 전환 · 실제 게시는 본인 테스트 영상만 · 광고 표시를 설정으로 · 감지 우회 옵션은 읽기용에만 · 남의 영상 재게시 금지(영상당 1개 규칙을 지키려고 테스트 영상을 새로 만듦) · 녹화는 사용자 화면을 덮지 않는 방식으로.

## 가장 어려웠던 것

전용 크롬에서만 자막이 0자로 오는 문제였습니다. 헤드리스·창 위치·Playwright·재생 차단을 하나씩 대조해 모두 원인에서 뺐고, Codex 조사와 직접 관측으로 **크롬 155가 조종 통로를 열면 켜는 '자동 조종 중' 표시**가 원인임을 찾았습니다(끄면 같은 영상에서 자막 16,606자). 겉증상만 보고 "대기 시간을 늘리자" 같은 땜질을 하지 않고, 대조군을 두고 원인을 확정한 뒤 고쳤습니다.

## 가점 항목

- 링크 직접 입력(실제 채널 확인 후 허용 범위 밖이면 거부) ✅
- 새 영상 초안 즉석 생성([다시 만들기]) ✅
- 프로필 고르기(설정에 프로필을 추가하면 선택 칸에 나타남) — 시연은 유튜브1 하나
- '뜨기 직전 영상 찾기'는 넣지 않았습니다 — 조회수 증가 속도를 지정 채널에서 실측했을 때 조건에 맞는 영상이 0개였고, YouTube API 정책상 파생 지표 계산에 별도 검토가 필요해서입니다.

## 면접에서 물을 만한 것

- **영상당 1개는 어떻게 막나요?** 게시 직전에 서버가 그 영상을 '진행 중'으로 먼저 기록합니다. 성공·결과불명이면 잠기고, 버튼을 누르기 전의 확실한 실패만 풀립니다. 화면 버튼을 막는 것만이 아니라 서버가 거절합니다.
- **하루 10개는 어디서 세나요?** 앱 전체 기준으로, 성공·결과불명·진행 중을 셉니다. 연습(게시 안 함)은 세지 않습니다.
- **링크를 직접 넣으면 남의 채널에도 달 수 있지 않나요?** 링크의 영상을 실제로 열어 채널 ID를 읽고, 지정 5곳이 아니면 초안 단계에서 막습니다.
- **AI가 없는 장면을 지어내면?** 근거 인용을 자막·설명 원문과 대조해, 없으면 다시 쓰게 합니다.
- **왜 실제로 남의 채널에 안 달았나요?** 시청자로 위장한 홍보는 플랫폼 정책·광고 표시 지침 위험이 있어, 기능은 그대로 만들고 실제 게시는 본인 테스트 영상으로 시연했습니다. 실제 운영이라면 광고 표시를 켜고 채널 주인과의 협의를 먼저 해야 한다고 봅니다.

## 한계와 다음 단계

- 유튜브 화면 구조가 바뀌면 댓글창 찾기가 깨질 수 있어, 실패 시 단계·이유·캡처를 남기게 했습니다.
- 자막이 정말 없는 영상은 제목·설명으로 쓰며, 그 사실을 화면과 AI 프롬프트에 표시합니다.
- 실제 운영으로 간다면: 광고 표시 켜기, 채널 주인 협의, 계정 여러 개의 분산 규칙, 사람 검토 단계를 먼저 넣겠습니다.
